************************************
Instructions for Teaching Assistants
************************************

.. contents::
  :depth: 2
  :local:

Responsibility
==============
#. Assignment grading

   * Labs - within one week
   * Projects - within two weeks

#. Student question answering through Discord, email, or Canvas.

Classroom 50 access
===================

Classroom 50 replaces the older GitHub Classroom workflow for this course.

* Accept the GitHub organization invitation sent by the instructor.
* Confirm membership in the ``classroom50-<classroom>-ta`` team when instructed.
* Sign in through the UWF `Classroom 50 portal
  <https://uwf-dsa-teaching.github.io>`_ using a GitHub Classic Personal
  Access Token (PAT). Do **not** use the standard OAuth sign-in; follow the
  PAT steps in :doc:`the Classroom 50 guide </course/classroom-50>`.
  Use this `pre-configured TA token generation link
  <https://github.com/settings/tokens/new?description=Classroom+50+TA+Sign-In&scopes=repo,workflow,admin:org,read:org,read:user,delete_repo>`_
  to create the token with the required scopes. Modify its expiration date to
  the end of the semester before generating it.
* Use the assignment accept link supplied by the instructor when you need to
  test an assignment.

Do not change classroom configuration or roster data unless the instructor
explicitly asks you to do so. When authorized, use the procedures below and
record the change for the instructor.

Testing an assignment
=====================

#. Obtain the assignment accept link or slug from the instructor.
#. Accept the assignment as a test account or TA account.
#. Clone the generated repository and complete representative tasks.
#. Push changes and verify that the configured Classroom 50 grading trigger
   runs successfully.
#. Inspect the resulting GitHub Release and ``result.json`` score details.

Student grading workflow
========================

Classroom 50 creates a repository for each accepted assignment and runs the
configured tests either on every push or in submit-only mode.

#. Open the Classroom 50 **Submissions** view or the student's repository.
#. Filter by assignment, section, or status, then inspect the latest Release and
   ``result.json`` output. Open the repository link from the student row when
   you need the exact code or Actions log.
#. Check the code briefly for required methods, neatness, and style when the
   rubric calls for manual review.
#. If feedback pull requests are enabled, leave line comments and suggestions
   in the student's feedback pull request.
#. Record the final grade in Canvas using the course rubric.

Roster binding correction
-------------------------

If a student selected the wrong roster name, open
``<org>/classroom50/<classroom-slug>/roster.csv`` and remove only that
student's ``username`` and ``github_id`` values. Keep the name and email,
commit the correction to ``main``, and ask the student to open the assignment
accept link again. They can then select the correct name.

Assignment template ownership
-----------------------------

When an instructor imports the shared ``assignments.json`` into a classroom,
the ``template.owner`` value must be changed to the section's teaching GitHub
organization. Do not leave the placeholder or use the shared organization as
the owner of student-facing repositories:

.. code-block:: json

   {
     "template": {
       "owner": "YOUR_TEACHING_ORGANIZATION",
       "repo": "dsa1-assignment-name",
       "branch": "main"
     }
   }

Verify the owner for every assignment before committing the file to
``<org>/classroom50/<classroom-slug>/assignments.json``.

Manual score override
---------------------

When the instructor authorizes a correction, edit
``<org>/classroom50/<classroom-slug>/scores.json`` and set ``override`` to
``true``. For example:

.. code-block:: json

   {
     "username": "student-handle",
     "score": 85,
     "override": true,
     "feedback": "Awarded partial credit for algorithm approach."
   }

Commit the change to ``main`` and notify the instructor.

Classroom 50 repository rules
=============================

Starter repositories must not retain legacy GitHub Classroom workflows or
autograding files under ``.github/``. Do not modify the provided ``Makefile``
or test configuration while grading. Classroom 50 may restore the Makefile
before running tests.

Technical prerequisites
=======================

* A working development environment; see :doc:`/cpp/ccpp-env`.
* C++, the CLI, :doc:`make </developer-tools/make>`, and
  :doc:`git </developer-tools/git>`.
* Familiarity with :doc:`Classroom 50 </course/classroom-50>`.

Common student support issues
=============================

* If a macOS student sees ``valgrind: command not found``, direct them to
  `GitHub Codespaces <https://github.com/features/codespaces>`_ and have them
  choose **Code -> Codespaces -> Create codespace on main**, then run
  ``make test-mem`` in the browser terminal.
* If a student sees ``Permission denied`` or HTTP 403, check whether the
  student is still shown as **Pending invite** in the web portal. They must
  accept the GitHub organization invitation sent to their university email.

Communication
=============

* Ask the instructor when you are unsure about a grading decision.
* Forward unclear student questions to the instructor.
* Use the teaching-chat channel on Discord as the primary staff channel.

Grading Workflow
----------------
#. Collect the automated grading results from Classroom 50.

   + Start with the Classroom 50 **Submissions** view.
   + If a score is missing, open the student's repository and inspect the
     latest GitHub Release and ``result.json`` output.
   + For late submissions, check the submission status and the timestamp of
     the commit or submission tag used for grading.

#. Manual grading

   + Briefly check the code for required methods, neatness, and style when the
     rubric calls for manual review.
   + Check that students implemented the required method rather than hardcoding
     results or replacing the required work with an unrelated library call.
   + If feedback pull requests are enabled, leave line comments and
     suggestions there.

#. Update grades on Canvas

   + Use SpeedGrader and the course rubric.
   + Apply late penalties according to the course policy.
   + Keep grades hidden until the instructor reviews and releases them.

.. note::

  More instructions are available in the :doc:`Classroom 50 guide
  </course/classroom-50>` and the :doc:`DSA project workflow
  </course/dsa-project>`.

Policies
========

* Late submissions follow the course policy. Apply penalties through Canvas as
  directed by the instructor.
* Re-submissions are allowed only when the student has a good reason.
* If a grading appeal is difficult to resolve, forward it to the instructor.

Hints
=====

* Fix a student's code only when the correction is very small and clearly
  within the course policy.
* Use tests for correctness. Read source code for neatness and style, not to
  replace the automated correctness checks.

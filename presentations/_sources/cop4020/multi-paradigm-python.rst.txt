What is Multi-Paradigm Programming?
-----------------------------------

* A programming language is **multi-paradigm** if it supports more than one
  programming paradigm.
* **Paradigm:** A way of thinking about and structuring programming problems
  and their solutions.
* Think of it like a **toolbox**: Different tools (paradigms) are better suited
  for different jobs.
* It allows developers to choose the most suitable style for a specific task or
  even mix styles within a single project.

Why Python?
-----------

* Python is inherently **multi-paradigm**. Its design philosophy emphasizes
  flexibility and readability.
* It doesn't force you into *one* specific way of structuring code.
* Core features support:

  * **Imperative** programming (statements, loops, conditionals).
  * **Object-Oriented** programming (classes, inheritance).
  * Elements of **Functional** programming (first-class functions, lambdas,
    map/filter).

* This flexibility makes Python powerful and applicable to a wide range of
  problems.

Paradigm 1: Imperative Programming
----------------------------------

* **Focus:** *How* to achieve a result.
* **Description:** Describes computation in terms of statements that change the
  program **state**.
* **Core Idea:** A sequence of commands for the computer to perform.
* **Characteristics:**

  * Explicit step-by-step instructions.
  * Use of mutable variables (state that can change).
  * Common constructs: loops (``for``, ``while``), conditionals
    (``if``/``else``), assignments (``=``).

* Often the first style learned by programmers.

Imperative Example in Python
----------------------------

* **Task:** Calculate the sum of numbers in a list.

.. code-block:: python

  def sum_list_imperative(numbers):
    total = 0  # Initialize state (mutable variable) for number in numbers: #
    Loop through sequence
      total += number # Change state
    return total

  my_list = [1, 2, 3, 4, 5] result = sum_list_imperative(my_list) print(f"The
  sum is: {result}") # Output: The sum is: 15

* This code explicitly tells the computer the steps: initialize ``total`` to 0,
  iterate, add each number to ``total``.

Paradigm 2: Object-Oriented Programming (OOP)
---------------------------------------------

* **Focus:** Organizing code around data, or "objects".
* **Description:** Bundles data (attributes) and the functions that operate on
  that data (methods) into **objects**.
* **Core Idea:** Model real-world or abstract entities using **classes**
  (blueprints) and **objects** (instances).
* **Key Principles:**

  * **Encapsulation:** Hiding internal state and requiring interaction through
    methods.
  * **Inheritance:** Creating new classes that reuse, extend, and modify
    behavior defined in other classes.
  * **Polymorphism:** Objects of different classes responding to the same
    method call in their own way.

OOP Example in Python
---------------------

* **Task:** Model a simple ``Dog``.

.. code-block:: python

  class Dog:
    # Constructor (initializes object state) def __init__(self, name, breed):
      self.name = name    # Attribute (data)
      self.breed = breed  # Attribute (data)

    # Method (behavior)
    def bark(self):
      return f"{self.name} says Woof!"

  # Create instances (objects) of the Dog class
  my_dog = Dog("Buddy", "Golden Retriever")
  your_dog = Dog("Lucy", "Poodle")

  # Call methods on the objects print(my_dog.bark())
  # Output: Buddy says Woof!
  print(your_dog.bark())  # Output: Lucy says Woof!
  print(f"{my_dog.name} is a {my_dog.breed}") # Accessing attributes

Paradigm 3: Functional Programming (FP)
---------------------------------------

* **Focus:** Computation as the evaluation of mathematical functions.
* **Description:** Treats functions as **first-class citizens**. Emphasizes
  **immutability** and avoiding **side effects**.
* **Core Idea:** *What* to compute rather than *how*. Focus on expressions that
  yield values.
* **Key Concepts:**

  * **Pure Functions:** Given the same input, always return the same output,
    and have no side effects (don't modify external state).
  * **Immutability:** Data structures cannot be changed after creation.
  * **First-Class Functions:** Functions can be passed as arguments, returned
    from other functions, and assigned to variables.
  * **Higher-Order Functions:** Functions that operate on other functions
    (e.g., ``map``, ``filter``).

Functional Example in Python
----------------------------

* **Task:** Get the squares of even numbers in a list.

.. code-block:: python

  # Using map, filter, and lambda (anonymous functions)
  numbers = [1, 2, 3, 4, 5, 6]

  # Filter out odd numbers
  even_numbers = filter(lambda x: x % 2 == 0, numbers)

  # Square the remaining numbers
  squared_evens = map(lambda x: x * x, even_numbers)

  # Convert iterator to list to see results
  result_fp = list(squared_evens)
  print(f"Squared evens (FP): {result_fp}")
  # Output: Squared evens (FP): [4, 16, 36]

  # --- Alternative using List Comprehension (Pythonic blend) ---
  result_lc = [x*x for x in numbers if x % 2 == 0]
  print(f"Squared evens (LC): {result_lc}")
  # Output: Squared evens (LC): [4, 16, 36]

* Focuses on transforming data (``filter``, ``map``) rather than modifying
  state in a loop. List comprehensions offer a concise, Pythonic way often
  inspired by functional concepts.

Python: Blending the Paradigms
------------------------------

* Python doesn't force purity. You can (and often do) mix styles.
* **Imperative:** Use loops and sequences for straightforward tasks.
* **OOP:** Use classes to model complex entities, manage state, and create
  reusable components (GUIs, data structures).
* **Functional:** Use ``map``, ``filter``, list comprehensions, and ``lambda``
  for data transformation and processing pipelines. Pass functions as arguments
  for flexible behavior (e.g., sorting keys, callbacks).

.. code-block:: python

  # Example: Using FP style within an OOP method class DataProcessor:
      def __init__(self, data):
          self.data = data # State (OOP)

      def get_processed_data(self, processing_func):
          # Using map (functional style) within a method return
          list(map(processing_func, self.data))

  processor = DataProcessor([1, 2, 3, 4])
  squares = processor.get_processed_data(lambda x: x * x)
  print(f"Processed data: {squares}")
  # Output: Processed data: [1, 4, 9, 16]


Benefits of a Multi-Paradigm Approach
-------------------------------------

* **Flexibility:** Choose the best tool (paradigm) for the specific problem
  you're solving.
* **Expressiveness:** Some problems are more naturally expressed in one
  paradigm than another.
* **Code Readability & Maintainability:** Using the appropriate paradigm can
  make code easier to understand and modify.
* **Leverage Libraries:** Many Python libraries utilize different paradigms
  (e.g., NumPy has imperative-style array operations, while functional tools
  exist for data pipelines).
* **Problem Decomposition:** Break down complex problems and use different
  paradigms for different parts.
